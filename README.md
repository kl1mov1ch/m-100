**M-100 — приложение для работы с объектами, таблицами и ежедневными отчётами команды.**
Сотрудник выбирает работу, вводит объём вручную, текстом или голосом, проверяет результат
и подтверждает запись. Администратор назначает объекты, управляет доступами и видит историю команды.

## Быстрый запуск

Нужны **Python 3.11–3.13** и интернет при первой установке зависимостей.
Если команда `python` недоступна в macOS/Linux, используйте `python3`.

```bash
git clone https://github.com/kl1mov1ch/m-100.git
cd m-100
python start.py
```

В Windows можно запустить `start.cmd` двойным щелчком или командой:

```powershell
.\start.cmd
```

Приложение подготовит отдельное окружение и откроется в браузере.
Первый запуск показывает **вымышленный пример**, без ключей и доступа к рабочим данным.
Для остановки нажмите `Ctrl+C` в окне запуска. Последующие запуски используют установленное окружение.

## Возможности

| Раздел | Что можно делать |
| --- | --- |
| **Проекты** | Создавать отдельные проекты, подключать Google-сметы, импортировать файлы |
| **Данные** | Искать по всем полям, добавлять и редактировать записи, удалять их из активной таблицы |
| **Учёт работ** | Вносить выполненные объёмы, исправлять итоги дня, видеть план и остаток |
| **Голос** | Диктовать прямо в приложении, видеть промежуточный текст, исправлять результат |
| **AI** | Превращать текстовый отчёт в позиции и объёмы с обязательной проверкой пользователем |
| **Отчёты** | Просматривать изменения за период и скачивать CSV для Excel |
| **Команда** | Назначать сотрудников на объекты, менять роли, отключать доступ |
| **Битрикс24** | Создавать один дневной отчёт по объекту и обновлять его при следующих подтверждениях |

Интерфейс адаптируется к ширине окна. На небольшом экране записи отображаются карточками,
на широком — таблицей. Небольшие анимации учитывают системную настройку уменьшения движения.

## Подключение своего аккаунта

1. Создайте папки `.local` и `.local/secrets` в корне проекта.
2. Скопируйте `.env.example` в `.local/account.env`.
3. Заполните ID своей Google Таблицы и точное название листа.
4. Поместите JSON-ключ сервисного аккаунта Google в `.local/secrets/google-service-account.json`.
5. Выдайте этому сервисному аккаунту права **редактора** на нужную таблицу.
6. Укажите свой Telegram ID в `ALLOWED_USER_IDS` и `ADMIN_USER_IDS`.

```powershell
.\start.cmd --account
```

Или на любой поддерживаемой ОС:

```bash
python start.py --account
```

Если приватный профиль уже подготовлен владельцем, повторять настройку не требуется.
Локальное открытие аккаунта не включает получение сообщений Telegram автоматически.

| Настройка | Назначение |
| --- | --- |
| `PROJECT_NAME` | Название основного объекта |
| `GOOGLE_SPREADSHEET_ID` | Часть ссылки между `/d/` и `/edit` |
| `GOOGLE_SHEET_NAME` | Точное имя вкладки, например `Лист1` |
| `GOOGLE_SERVICE_ACCOUNT_FILE` | Путь к личному JSON-ключу Google |
| `ADMIN_USER_IDS` | Telegram ID владельцев приложения |
| `ALLOWED_USER_IDS` | ID первоначально разрешённых пользователей |
| `LLM_API_KEY` | Необязательный ключ AI; ручной ввод доступен без него |
| `TELEGRAM_BOT_TOKEN` | Токен своего бота для режима Telegram |

## Таблицы: два сценария

### Рабочая Google-смета

В управлении выберите **«Подключить Google Таблицу → Рабочая смета — запись в Google»**.
Поддерживается разметка: **B — название, C — единица, D — план, строка 3 — даты,
дневные объёмы — начиная с J**. Права записи проверяются при подключении без изменения данных.
Даты распознаются в числовом, международном, русском и однозначно определяемом американском формате.
Противоречивые или повторяющиеся даты требуют уточнения перед записью.

Сотрудник открывает **«Добавить»**, выбирает позицию и объём, проверяет черновик и подтверждает.
Только после подтверждения изменяются дневные значения Google и итоговая формула объёма.
Для одной рабочей Google-таблицы используйте одну активную пишущую копию приложения;
независимые локальные копии не координируют одновременную запись между собой.
AI и голос не записывают данные автоматически.

### Произвольная таблица

Импортируются **XLSX, XLSM, XLS, ODS, CSV, TSV, TXT и JSON**. Можно выбрать лист и строку заголовков;
значение `0` означает отсутствие заголовков. Порядок, пустые и повторяющиеся названия колонок допустимы.

Импорт создаёт **отдельную копию данных проекта**. Исходный файл или Google-источник не изменяется.
Формулы не пересчитываются, оформление книги не воспроизводится в редакторе; оригинал загрузки сохраняется приватно.
Для учёта объёмов можно дополнительно назначить колонки названия, единицы, плана и кода.

Ограничения одного импорта: **12 МБ, 25 листов; на лист — 5 000 строк, 100 колонок и 250 000 ячеек**.
Превышение ограничений вызывает понятную ошибку, а не незаметное обрезание данных.

## Сотрудники и доступ

Сотрудник узнаёт свой ID командой `/id` в боте. Администратор открывает
**«Управление → Объекты и сотрудники → Назначить сотрудника»**, вводит ID, имя и сохраняет назначение.

- **Мастер** работает только с назначенным объектом и не может переключать объекты самостоятельно.
- **Администратор** управляет объектами, назначениями и доступами, видит журнал всей команды с авторами правок.
- **Владелец** защищён от отключения через панель. Пользователь не может изменить собственные права.

Для переназначения есть **«Изменить объект / роль»**. Новое назначение действует на следующие запросы;
открытая старая форма не сможет записать данные в другой объект.

Локальный режим открывает права владельца только на этом компьютере. В режиме Mini App
вход проверяется подписью Telegram и разрешённым ID; обычная ссылка не даёт доступа к данным.

## Голос и AI

```bash
python start.py --voice
# или с личным профилем
python start.py --account --voice
```

При первом включении голоса загрузится небольшая русская модель **Vosk** с официального сайта.
После загрузки живое распознавание выполняется локально, без API-ключа и оплаты за запросы.
Нужны разрешение на микрофон и браузер с поддержкой AudioWorklet. Одновременно обрабатывается одна запись,
продолжительность — до трёх минут. Для готовых аудиофайлов в этом режиме дополнительно нужен `ffmpeg` в PATH.

Нажмите **«Голос → Начать запись»**: промежуточный текст появится в поле во время речи.
Остановите запись, проверьте слова и числа, затем используйте результат. Точность зависит от шума,
микрофона и произношения; небольшая модель может ошибаться в профессиональных терминах.

Для разбора отчётов по смыслу предусмотрен совместимый AI API. Пример конфигурации использует Groq.
Нужен собственный ключ; бесплатные тарифы имеют ограничения. Приложение подбирает небольшой список
кандидатов вместо отправки всей сметы. При лимите, ошибке ответа или недоступности AI остаётся ручной ввод.
Платный резервный сервис автоматически не подключается.

## Битрикс24

В **«Управление → Битрикс24»** вставьте входящий вебхук своего портала с правами CRM и укажите ID воронки
(`0` — основная). Доступность REST API определяется возможностями аккаунта Битрикс24.
Проверка подключения не создаёт пробную сделку. Секретный адрес не возвращается в интерфейс и журнал.

После подтверждения объёмов отчёт сохраняется в долговечной очереди. Создаётся **одна сделка на объект и дату**,
следующее подтверждение обновляет итог этого дня. После потерянного ответа сначала проверяется существующая сделка.
Ошибки CRM не блокируют дальнейшую работу с таблицей. Очередь сохраняется после перезапуска,
синхронизация выполняется каждую минуту и по команде администратора. Пока запись не подтверждена CRM,
отображается ожидание, а не сообщение об успешной отправке.

## Telegram Mini App

Для работы внутри Telegram заполните `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` и `MINIAPP_URL` в личном профиле.
Адрес Mini App должен использовать **HTTPS**. Затем:

```bash
python start.py --telegram
```

Один токен должен использоваться только одним процессом получения сообщений. Локальный режим `--account`
можно применять для проверки интерфейса без включения этого режима.

Команды: `/start`, `/id`, `/draft`, `/today`, `/report`, `/edit`, `/find`, `/remain`, `/retry`, `/cancel`.
Ввод и подтверждение доступны также через русские кнопки приложения.

## Как устроен проект

```text
m-100/
├── README.md                 # функции, запуск и подключение
├── start.py / start.cmd      # подготовка окружения и запуск
├── pyproject.toml            # зависимости и параметры качества
├── .env.example              # образец без личных значений
├── src/stroybot/
│   ├── local.py              # локальный запуск и профили
│   ├── miniapp.py            # API, проверка доступа, голосовой поток
│   ├── service.py            # черновики, подтверждение и восстановление
│   ├── domain.py             # позиции, объёмы, даты и проверки
│   ├── gateways.py           # Google Sheets и Битрикс24
│   ├── access.py / crm.py    # роли, проекты и очередь CRM
│   ├── tabular.py            # импорт и независимые табличные проекты
│   ├── recognition.py        # AI-разбор и распознавание аудио
│   ├── voice_service.py      # локальное распознавание Vosk
│   ├── store.py / reports.py # SQLite и выгрузка истории
│   ├── bot.py                # команды и диалоги Telegram
│   ├── static/               # интерфейс без отдельной сборки frontend
│   └── assets/               # вымышленные примеры
├── tests/                    # проверки логики и интерфейсных алгоритмов
├── scripts/check_secrets.py  # проверка публикуемых файлов
├── .github/workflows/ci.yml  # автоматические проверки
└── .local/                   # только ваши настройки и данные; Git игнорирует папку
```

Приложение использует Python, aiohttp, aiogram, SQLite и обычные HTML/CSS/JavaScript.
Запись начинается с сохранения намерения в журнале. Повтор запроса сверяется с текущим состоянием,
поэтому после тайм-аута объём не прибавляется второй раз. Устаревшие черновики, изменившиеся значения,
неверные единицы и спорные результаты AI требуют проверки пользователем.

## Проверки и публикация

```bash
python -m pip install -e ".[dev]"
python -m pytest -q
python -m ruff check src scripts start.py
python scripts/check_secrets.py
node --test tests/search.test.cjs tests/pcm.test.cjs
```

Node.js нужен только для двух проверок JavaScript, обычному запуску приложения он не требуется.
GitHub Actions проверяет проект на Windows и Linux с Python 3.11, 3.12 и 3.13.
Наличие workflow не означает, что проверки уже выполнялись в вашем новом репозитории.

**В GitHub передаётся код, а не личный профиль.** `.local`, заполненные `.env`, ключи, базы,
загрузки и окружение исключены через `.gitignore`. Проверка ищет известные форматы ключей и
совпадения с текущим приватным профилем, не печатая сами значения. Перед публикацией выполните её
и проверьте `git status`. Это дополнительная проверка, а не гарантия обнаружения любого секрета.

## Перенос на другой компьютер

Скачайте репозиторий и выполните `python start.py`. Для личного аккаунта отдельно перенесите
`.local/account.env` и `.local/secrets` доверенным способом. При необходимости перенесите
`.local/account` с журналами и назначениями. Не публикуйте эти папки в GitHub.

Окружение `.venv` переносить не требуется: запуск создаёт его заново. Пути внутри приватного профиля
должны оставаться относительными к папке проекта. Вымышленный профиль и личный профиль хранят данные раздельно.

## Если что-то не открывается

| Ситуация | Что проверить |
| --- | --- |
| Python не найден | Установите Python 3.11–3.13 и включите добавление в PATH |
| Первая установка не завершилась | Проверьте интернет и повторите ту же команду |
| Порт занят | Закройте старую копию или добавьте `--port 8767` |
| Страница открыта без доступа | Запустите приложение обычной командой: оно откроет окно с локальным входом |
| Google возвращает 403 | Выдайте сервисному аккаунту права редактора на конкретную таблицу |
| Лист не найден | Проверьте точное название вкладки, включая пробелы |
| AI исчерпал лимит | Внесите объём вручную или повторите позже |
| Не работает микрофон | Разрешите доступ в браузере или воспользуйтесь текстовым вводом |
| CRM ожидает | Проверьте подключение в управлении; сохранённые объёмы повторно вводить не нужно |

Проверить личное подключение без внесения объёмов: `python start.py --account --check`.

## Разработка с AI

Для разработки использовался Codex: логика отчётов, интеграции, интерфейс и автоматические тесты.
Результат проверялся тестами Python и JavaScript, ручными сценариями интерфейса и отдельной проверкой подключений.
Точность настоящей LLM и полная отправка отчёта в CRM требуют отдельной приёмки с настроенными учётными данными.
Демонстрационный запуск не подтверждает готовность ваших внешних подключений.
